It's the translation counterpart of the ASR benchmark you already ran, and it exists to answer one question: **which translation model should the program use?**

With `asr_benchmark.py` you ran four Whisper models on the same Armenian clips, and the results showed `large-v3-turbo` was the most accurate model that fit the 2 s budget. `mt_benchmark.py` does the same for the five translation candidates in PLAN.md (NLLB 600M, NLLB 1.3B, M2M100, MADLAD-400 and OPUS-MT). Without it, `MT_MODEL` would just be my guess, and PLAN.md and INSTRUCTIONS.md both say model choices are decided by benchmarks on this laptop.

**How it works.** It takes the 200 FLEURS Armenian sentences you already transcribed, and every candidate translates each sentence twice:

- **From the correct Armenian text.** This shows how good the model is with perfect input.
- **From your large-v3-turbo transcripts.** This shows how it copes with real ASR mistakes, which is what happens live. It is PLAN.md risk 3: translation errors piling on ASR errors.

Each translation is compared with the human English translation of the same sentence from FLEURS en_us. Each model then gets:

- **chrF++ and BLEU:** standard 0–100 scores for how close the output is to the human translation (higher is better).
- **Mean, p95 and max time per sentence,** and how many translations went over the 0.5 s translation budget from PLAN.md §2.

**What you get.** A Markdown table with one row per model, and one CSV per model in `benchmarks/results/` with the translations side by side, so you can also read them yourself. You pick the most accurate model that fits 0.5 s. I set `MT_MODEL` to it, and the table goes into the README as the "model choices with alternatives and reasons" the brief asks for.

**What it isn't.** It isn't part of the running program. Like the ASR benchmark, you run it once (or again if you change models), and the program never imports it.

If you'd rather skip the comparison and just pick a model, NLLB-600M is a reasonable default. You'd lose the measured justification for the README, though, and with it the evidence that translation fits the 5 s latency limit.
